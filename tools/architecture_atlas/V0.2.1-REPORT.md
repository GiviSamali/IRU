## Architecture Anomaly Detection

Добавлена независимая панель «Аномалии»: сироты, тупики, изолированные и центры. Изолированные исключены из обычных сирот/тупиков; high-degree может пересекаться с сиротой или тупиком и отражает другую характеристику. Для каждого узла доступны подсистема, тип/роль, подтверждение, in/out/total degree, уникальные соседи, типы рёбер, source evidence и фокус/явное открытие сведений.

По умолчанию — весь снимок, все слои, `import` + `static_call`, без `contains`. Семантический профиль — `implements` + `depends_on`. Есть смешанный профиль, явные checkbox типов, область видимого подграфа или конкретной подсистемы, фильтр logical/physical, сортировки, настраиваемые threshold/Top N. Подграф индуцированный: оба конца ребра должны входить в выбранную область/слой. Поэтому пограничные отношения в таком подграфе не учитываются, что прямо указано в metadata.

Смешанный режим по умолчанию исключает производное `depends_on`, если его evidence.source_edge_id также входит в рассчитанный граф. Альтернатива «Считать все проекции отдельно» допускает одновременный учёт, явно показывая `raw`. Несколько семантических уровней являются отдельными рёбрами проекции; их degree не эквивалентен числу операций или независимых runtime-каналов.

Показываются выбранные/реально использованные типы, область, число узлов/рёбер, политика и число исключённых derived edges. Runtime observed не учитывается. Иерархия может быть включена только явным выбором `contains`; результаты такого анализа не называются использованием функции.

Диагностика считается при загрузке/изменении параметров, не в WebGL frame loop. Хранятся индексы records и выбранных edge IDs. Списки имеют пагинацию по 30 записей, evidence DOM создаётся по раскрытию. Закрытие панели сохраняет результаты и выбранные параметры. «Сбросить диагностику» снимает только её подсветку.

## Interactive Shortest Path

«Путь между узлами» включает явный режим. Первый клик выбирает A, второй по другому узлу — B; последующие клики меняют B. BFS переиспользует существующие исходящие индексы `model.route`, соблюдает направление и выбранные типы, пропускает inferred/runtime relations. Дополнительные поля результата — упорядоченные source/target/type/direction/evidence, не events Execution Trace.

Подпись: «Кратчайший путь по выбранным архитектурным связям». Если пути нет: «Маршрут не найден», типы, объяснение неполноты модели, возможность поменять A/B или фильтры. Нет LLM и выдуманных соединений.

Внизу — отдельная панель маршрута: A/B, swap, новая B, сброс, выход, типы и переходы. Каждый переход имеет evidence, ссылку на код, фокус камеры и явную кнопку сведений. Маршрут золотистый, все участники выделены, остальные приглушены. Никакой статической анимации молнии. Весь граф/координаты сохраняются; при смене шага обновляются цвета и нужная видимость, без новых mesh/materials.

Проверенный пример по реальным сущностям, типы `import` + `static_call`, два перехода:

`orchestrator.run_turn → response_presentation.normalized_worker_report → worker_reports.build_worker_report`

1. `run_turn → normalized_worker_report`, static_call, forward; [orchestrator.py:291](https://github.com/GiviSamali/IRU/blob/ee3cc4971e5b88f9853e36cef38e7e986f7fd858/server/orchestrator.py#L291).
2. `normalized_worker_report → build_worker_report`, static_call, forward; [response_presentation.py:95](https://github.com/GiviSamali/IRU/blob/ee3cc4971e5b88f9853e36cef38e7e986f7fd858/server/response_presentation.py#L95).

Это существующий статический маршрут. Участие в конкретном запросе не утверждается. Для Web UI → записи файла маршрут может отсутствовать из-за неполного JS/event/callback покрытия — недостающие рёбра не добавляются.

## Совместимость взаимодействий

Начальный Overview без выделения, правая панель закрыта. Обычный одинарный выбор не открывает панель; двойной открывает сведения, дерево раскрывается отдельной ▸. Правая панель хранит свой detailsNode независимо от A/B. В режиме пути двойной щелчок не открывает случайную карточку и не выбирает лишнюю точку. Перетаскивание камеры не считается кликом.

Reducer разделяет normal selection, diagnostic highlight, path result и execution activity. Сброс выделения не сбрасывает путь/диагностику/Trace; сброс пути не стирает импортированную трассу; сброс диагностики не удаляет результаты анализа. Остановка Trace сохраняет файл/курсор, но снимает его активную подсветку. Каждый активный слой подписан в легенде.

Вход в Execution скрывает панель статического пути и отображает только событийный edge, сохраняя найденный путь отдельно. Вход в путь или выбор диагностической записи останавливает показ Execution и явно переключает режим. Importer, same-SHA validation, DEMO / SYNTHETIC и gaps сохранены. Статический результат не преобразуется в Trace; pulse берётся только из импортированного события и при активном Execution.
