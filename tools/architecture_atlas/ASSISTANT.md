# Инженерный помощник атласа — первая версия

## Запуск

```powershell
cd 'C:\Users\russa\OneDrive\Desktop\IRU\tools\architecture_atlas'
python assistant/server.py --port 8774
```

Или запустить Start-AtlasAssistant.ps1. Открыть http://127.0.0.1:8774/ → Помощник → Настройки DeepSeek. Ввести API-ключ в локальное поле и сохранить. Поле модели по умолчанию deepseek-v4-pro; его можно изменить на доступную в вашем аккаунте модель с tool calls. Ключ в чат Codex передавать не нужно.

Можно вместо формы задать DEEPSEEK_API_KEY и ATLAS_LLM_MODEL в окружении процесса сервера. Переменные имеют приоритет перед сохранёнными настройками.

Обычный python -m http.server и старый node scripts/serve.mjs дают только статическую карту; для LLM нужен assistant/server.py. Все Python зависимости — стандартная библиотека, дополнительных pip-пакетов нет.

## Возможности

- Поиск/описание узлов, прямые зависимости, чтение конкретных строк исходников с SHA.
- Поиск по исходникам, документации и тестам закреплённого снимка, доступным на ПК.
- До трёх ограниченных маршрутов; компоненты связности/центры и условное удаление узлов. Никакого вывода о runtime-отказе из одной топологии.
- Выбор/фокус, масштаб, раскрытие, режимы/фильтры, карточки, маршруты, подсветка, общие направления, вращение, качество и свечение.
- Открытие дерева, важных узлов и диагностики; существующие команды общего вида и статической/синтетической трассы.
- История нескольких диалогов и закреплённые заметки с commit. При смене SHA старая история остаётся помеченной старым SHA.
- Локальное сравнение файла с другим экспортированным снимком, если его manifest доступен; сохранённая история commit.
- Для команд карты: сервер выдаёт ID, текущая вкладка выполняет разрешённое действие и возвращает фактическую квитанцию. Без квитанции результат неизвестен. Команды другой вкладки не принимаются.

## Данные и ограничения

Ключ и диалог находятся в .local/ (не включать в Git/архив). Backend-код и .local не раздаются статическим сервером. Сервер слушает только loopback, проверяет Host/Origin, не разрешает CORS и не даёт модели shell/произвольный HTTP/редактирование файлов. Исходники читаются только из manifest того же SHA; traversal и другой снимок отклоняются. Найденные фрагменты исходников и вопросы передаются выбранному DeepSeek API. Это именно API-интеграция, не офлайн-модель на телефоне.

Текущая рабочая копия production не читается автоматически. По умолчанию используется .atlas-sources/latest.json; SHA должен совпадать с data/architecture.json. Можно передать --source-root. Если полного снимка нет, доступны только bundled review-source (ограничение видно в статусе).

Система не знает live состояние IRU, пока оно не предоставлено отдельно; статический граф не покрывает все динамические вызовы. Нельзя гарантировать ответ на любой вопрос. Ограничены длины данных, время (8 минут), шаги (18) и tool batch (8). История в запросе ограничена 24 сообщениями/36 тысячами символов; вся локальная история сохраняется. Остановка прерывает следующие шаги, но уже отправленный HTTP запрос провайдера может завершиться до timeout; подтверждённые действия карты не откатываются.

## Проверка

```powershell
python assistant/test_assistant.py
```

Локальные проверки источников, направленных маршрутов, сценария удаления, схем, сохранения памяти, ожидания квитанции/отмены, HTTP private files/Origin. Они не вызывают DeepSeek. browser_check.py — отдельная явно обозначенная локальная fixture для проверки полного браузерного протокола, не рабочая LLM и не fallback. Реальный API-проход проверяется только с настроенным пользовательским ключом.

Официальный контракт API: https://api-docs.deepseek.com/api/create-chat-completion/
