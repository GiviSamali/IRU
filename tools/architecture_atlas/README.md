## Навигация

Клик выделяет узел и точные входящие/исходящие отношения; двойной клик открывает сведения. Потомки раскрываются отдельной кнопкой ▸ в дереве. Панель показывает назначение, ответственность, роли, реализации, входы/выходы, границы доверия, evidence и неизвестные сведения. Все вторичные implements-роли доступны из панели без копий исходников. Основной родитель модуля — первая проверенная привязка; другие механизмы доступны через отношения.

«Архитектура» возвращает обзор компонентов. «Полный граф» включает все узлы. «Исходники» переключает дерево на физические реализации. Поиск видит скрытые узлы. Фильтры типов/направлений, транзитивный обход и маршруты используют существующие отношения; список переходов позволяет рассмотреть каждый шаг. Это статический архитектурный путь, не runtime trace.

Мышь вращает камеру, колесо масштабирует, правая кнопка перемещает. «Ядро», «Созвездие», «Фокус узла», «Общий вид» сохраняют ориентацию при плавном переходе. Подписи зависят от роли/расстояния, максимум 80. Свечение управляется отдельно. Выбор и раскрытие не меняют координаты.

## Семантика и обновление

`scripts/extract.py` читает tracked исходники server/agent/ui/browser_extension и строит AST graph, не импортируя production-модули. `scripts/semantic_catalog.py` — поддерживаемый каталог проверенных определений; `scripts/semantics.py` добавляет роли, implements, contains и агрегированные depends_on с evidence. Отсутствующая привязка вызывает ошибку. Неклассифицированные модули остаются явно inferred.

Обновление: `python scripts/extract.py`, при необходимости `--repo PATH --output PATH`. После изменения кода проверьте каталог/evidence. Implementation/static edge IDs сохраняются для неизменившихся сущностей. Схема снимка — 2. Координаты стабильны для одинакового полного снимка; новый состав семейства может изменить раскладку.

Confirmed source, verified architectural mapping, static dependency, logical taxonomy и inferred различаются. Агрегированные зависимости ссылаются на исходные статические рёбра. Ни одна новая функциональная связь не считается runtime observed.

## Execution Explorer — совместимость v0.1

Импорт JSON до 5 MiB / 10 000 событий работает локально. Поддерживаются Trace events, task diagnostic_trace или commands, worker_report/presentation snapshots. diagnostic_trace имеет приоритет над commands. Неполные/неизвестные переходы остаются gaps; участники не достраиваются. Sequence/время неубывающие, event IDs уникальны.

Импульс разрешён только по явно указанному исходному ребру, согласованному с соседними событиями и architecture_version == git_sha. Semantic edges исключены. Версия трассы не меняется автоматически: старый SHA сохраняет доступные события/ID, но переходы не переутверждаются для нового снимка. DEMO / SYNTHETIC остаётся отдельно подписанной синтетической демонстрацией.

Сохранены timeline, pause/steps/speed/event focus. Условный интервал — 1.2 s на событие; точные длительности/параллельность не реконструируются. Команды не исполняются. Поля отображаются через textContent; command/arguments/raw stdout/results не выводятся. Используйте обезличенные snapshots: автоматическое выявление всех секретов невозможно. Execution Mapping в v0.2 не разрабатывается.

## v0.2.1: диагностика и кратчайший путь

Добавлены «Аномалии» и «Путь между узлами». Диагностика по умолчанию считает весь снимок по import/static_call без contains. Семантическая связность анализируется отдельно; смешанный режим исключает derived depends_on при учёте его source edge. Область, типы и политика отображаются явно; доступны порог/Top N, сортировка и evidence. Результаты — сигналы статической модели, не доказательство неиспользования кода или единой точки отказа.

Режим пути: первый клик A, второй B; BFS соблюдает направление и фильтры. Есть swap, новая B, сброс, выход и переходы с исходниками. Обычный клик вне этого режима только выделяет узел, двойной открывает независимые сведения; дерево раскрывается кнопкой ▸. Сброс выделения, диагностики, маршрута и остановка Execution раздельные. Статический путь не запускает молнию и не превращается в Trace.

Подробности, Top 10 и пример: [V0.2.1-REPORT.md](V0.2.1-REPORT.md). Машинный отчёт: data/diagnostic-summary.json; обновление: node scripts/diagnostic_report.mjs.

## v0.4: Ambient Life / «ночной город»

В покое полный граф живёт как ночной город: фоновые узлы имеют независимые плавные ритмы яркости с периодами 8–18 секунд. Связи стали светлее и слабо меняют прозрачность по районам. Орбита камеры — примерно один оборот за четыре минуты, с постоянной дистанцией и без автоматического зума. Ручное управление приостанавливает орбиту; возобновление — через 5 секунд после отпускания. Координаты узлов и архитектурные данные не меняются, оттенки сохраняются.

Яркость усилена и вращение добавлено по явным уточнениям пользователя после первого этапа. Ореол ядра сохраняет цикл 9 секунд, яркость ±10% и размер ±5%; подсистемы — 8,5–12,7 секунды, яркость ±5%, размер ±2,5%. Отдельные огни рассчитываются в существующем instanced-шейдере, без CPU-обхода графа каждый кадр и без новых объектов.

При входе в Execution декоративные огни гаснут, фон затемняется и орбита останавливается; текущие функциональные участники сохраняют подсветку. Триггер — существующий режим Execution/локальная трасса, а не догадка об активности IRU. При возвращении в Architecture/Relationships освещение плавно возобновляется. Эффект декоративный, не доказательство выполнения.

При `prefers-reduced-motion: reduce` и скрытой вкладке анимация приостановлена. `/?ambient=off` отключает декоративное освещение и орбиту; `/?orbit=off` — только орбиту. Пункт «Свечение → Выкл.» отключает декоративное освещение. Функциональное затемнение режима Execution сохраняется. Новых панелей и зависимостей нет.

Параметры, замеры производительности и границы проверки: [V0.4-REPORT.md](V0.4-REPORT.md).
