# IRU Living Architecture v0.2 — implementation report

Исходный HEAD: `ee3cc4971e5b88f9853e36cef38e7e986f7fd858`, ветка `codex/agentshell-webview`. Реализованы только Architecture Semantics и Spatial Engine. Production не изменяется. Runtime mapping не развивается.

## Architecture Semantics

Отдельный поддерживаемый каталог `scripts/semantic_catalog.py` содержит определения ответственности, входов/выходов, границ доверия и привязок к существующим определениям. `scripts/semantics.py` накладывает его на прежний AST graph. Отсутствующий модуль/символ вызывает ошибку построения снимка, а не молчаливую потерю роли. Evidence содержит путь, символ, диапазон строк, SHA и объяснение.

Принадлежность основана на просмотренных контрактах и реализациях, не на именах файлов. Например, Worker context проверяет владельца чата/результатов и явно исключает историческую authority; Scheduler использует owner-scoped очередь; Worker вызывает существующий controller; Presentation отбирает verified artifacts. Функциональные группы — инженерная классификация, не новые сервисы.

**35 модулей** получили явные роли, **83** сохраняются в видимых контейнерах «Непривязанные реализации». Их прежняя эвристическая привязка отмечена `inferred`. У неподтверждённых полей показывается «не установлен», а не предполагаемый контракт. Каталог не означает полное покрытие каждого helper внутри модуля.

Идентификаторы исходников не менялись. Модуль имеет одного родителя в дереве и несколько `implements` отношений. Например, `server/task_runtime.py` участвует в Worker lifecycle, multi-device и command transport; `controller_shared.py` — в context, memory и confirmation. Одна функция не размножается в графе. Канонический родитель модуля — первая проверенная привязка; остальные реализации доступны через роли и панель механизма. Функциональная роль конкретной функции не наследуется автоматически из всех ролей файла.

Классы/функции остаются физическими сущностями; методы различаются по AST-родителю. Декораторы HTTP/WebSocket помечают дополнительные kind_tags, не создавая копий обработчиков. JS по-прежнему извлечён только до модулей; отдельный JS AST не добавлялся.

`depends_on` агрегируются из сохранившихся статических рёбер между явно привязанными реализациями, на уровне механизмов, компонентов и подсистем. Каждое такое ребро ссылается на исходный static edge и его source evidence. Это проекция статических зависимостей, а не новые прямые runtime-вызовы. `contains` отдельно представляет навигацию. Статусы `confirmed_source`, `verified_architectural_mapping`, `static_dependency`, `logical_taxonomy`, `inferred` явно разделены. `runtime_observed` не присваивается.

Конкретные канонические пути:

1. IRU → Управление задачами → Worker → Tool execution loop → `server/controller_non_pipeline.py` → `process_non_pipeline_command`.
2. IRU → Интеллект и понимание → Orchestrator → Decision contract → `server/orchestrator.py` → `decide`.
3. IRU → Контроль результатов и доказательства → Worker Report → Outcome report projection → `server/worker_reports.py` → `build_worker_report`.
4. IRU → Исполнение и устройства → Device Execution → Agent dispatch → `agent/core/runtime.py` → `AgentRuntime` → `_handle_command`.

Дополнительная роль terminal validation для `run_journal.validate_answer_text_payload` показана через `implements`; основной модуль журнала расположен под Run step journal. В панели механизма доступны все явно привязанные реализации, даже если их основной родитель — другой механизм.

Не установлены отдельные provider adapter компоненты, полный event/callback graph, все ошибки/границы каждой подсистемы и полная семантика JS. Они перечислены как ограничения, не созданы как фиктивные узлы.

## Spatial Engine

`src/spatial.mjs` вычисляет одну детерминированную раскладку для всех узлов. IRU — `[0,0,0]`; семь подсистем распределены Fibonacci sampling по оболочке радиуса 190 с настоящими X/Y/Z координатами. Дочерние семейства используют меньшие вложенные объёмные оболочки, отсортированные устойчивые ID и фиксированный phase родителя. Density factor ограничен; раскрытие/выбор не пересчитывают координаты. Изменение состава семейства при новом снимке может изменить его раскладку — стабильность гарантируется для одного и того же полного снимка.

Камера плавно летит к узлу/региону, сохраняет текущее направление обзора и имеет min/max distance. Общий вид рассчитывает расстояние по полным bounds и aspect viewport. Есть отдельные действия «Ядро», «Созвездие», «Фокус узла», «Архитектура», «Полный граф». Режимы используют одну модель. «Исходники» переключает дерево на физические сущности, поиск остаётся общим.

Подсветка использует индексы смежности и **точные ID рёбер**, учитывает тип и направление. Связь между двумя соседями выбранного узла сама по себе больше не подсвечивается. Транзитивный обход подсвечивает только пройденные отношения. Найденный направленный маршрут имеет список переходов с навигацией; ненайденный не достраивается. Структурные линии заметно слабее архитектурных. Контекстные связанные реализации могут быть показаны без раскрытия всего их родительского дерева.

Свечение — экономичные radial DataTexture sprites: ядро, семь центров и выбранный узел. Нет глобального bloom, новых зависимостей и постоянно движущихся декоративных точек. Яркость выделения, additive glow и затухание по глубине несут смысл. Свечение выключается или ослабляется отдельно. Ядро имеет небольшой стабильный foreground accent для читаемости в плотной сети.

Один переиспользуемый InstancedMesh для всех узлов и один буферизованный LineSegments для всех рёбер. При выделении обновляются состояния/цвета; meshes/materials не пересоздаются. При изменении видимости обновляются instance matrices/edge positions. Невидимые рёбра имеют нулевую длину и alpha=0, но сохраняются в модели и буфере. Графические ресурсы освобождаются при pagehide. Подписи ограничены 80 DOM элементами, отбираются по расстоянию и роли; selected имеет приоритет, пересечения подавляются. Camera/label refresh не меняют graph IDs/coordinates.

Полный граф содержит все **1 233 узла / 3 272 ребра**; фильтры могут управлять отображением, не удаляя данные. GPU/FPS, сложные перекрытия кластеров и поведение на обычном ноутбуке **не измерялись**: без разрешения владельца тесты не запускались. Подготовлен CPU budget test, а WebGL performance требует отдельной ручной приёмки. Сферическая раскладка не гарантирует математически оптимального устранения всех пересечений.

## Execution compatibility

Сохранены существующий importer, timeline, player, DEMO / SYNTHETIC и gaps. Блок воспроизведения не переписывался. Дополнительно pulseEdge исключает semantic edges даже при прямой передаче event. Новые logical/implements/contains/derived dependencies не получают runtime eligibility. Старые implementation/static edge IDs сохранены.

Схема снимка теперь `schema_version=2`, `semantic_version=0.2`, `snapshot_id=<SHA>:semantics-0.2`. Прежний importer продолжает использовать `architecture_version == git_sha`. События старого SHA сопоставляются с сохранившимися исходными узлами, но их переходы остаются gaps до предоставления трассы соответствующей версии. Автоматического изменения версии трассы или подстановки семантических маршрутов нет. Данные v0.1 с прежними ID не теряют сущности при таком отображении.
