# Ветки и обновление сервера

Рабочая ветка текущей интеграции — `codex/deeptalk-integration`.
`main` — базовая ветка релизов. До отдельного выпуска интеграции в main
сервер тестирует явно выбранную рабочую ветку. Переключение на main само по
себе не является обновлением: оно может убрать ещё не выпущенные функции.

## Что привело к регрессии

После разделения веток в main появились `b1a1714` (Yandex-поиск без
подключённого устройства) и `30d5c57` (слово «усни»), а PLAN продолжал
развиваться в интеграционной ветке. Выкладка этой ветки без переноса main
убирала оба изменения. Main необходимо объединять с рабочей веткой перед
полным тестированием и выпуском, а не восстанавливать отдельные функции вручную.

## Порядок работы

1. Перед изменениями выполнить `git fetch origin` и проверить ветку/status.
2. Перед выкладкой включить актуальный `origin/main` в рабочую ветку,
   разрешить конфликты и выполнить связанные тесты и полный pytest.
3. Push рабочей ветки. На сервере обновлять только явно названную ветку.
4. Выпуск в main — отдельный проверенный fast-forward/merge согласованного
   состояния; новые задачи начинать от обновлённого main.
5. Не переключать production между альтернативными историческими ветками.

## Проверяемое обновление

После получения этого скрипта на сервере вместо обычного pull использовать:

```bash
cd /opt/iru/app
python3 tools/update_server.py --branch codex/deeptalk-integration --restart
```

Скрипт сначала обновляет remote refs, проверяет текущую ветку, чистоту
отслеживаемых файлов, включение origin/main в целевую ветку и возможность
fast-forward. При ошибке код и сервис не обновляются. `--check` выполняет
только проверку, без слияния и рестарта. Скрипт не переключает ветки,
не удаляет локальные файлы и не разрешает конфликты на production.
После изменения frontend нужен Ctrl+F5. Проверять надо также выведенный SHA.

## Исторические ветки

На момент аудита 58 удалённых веток уже входили в историю рабочей ветки.
Вне неё также есть backup и старые альтернативные реализации контроллера,
инструментов и sandbox. Их нельзя массово сливать: это может восстановить
отменённые решения. Они сохранены для истории; автоматического удаления нет.
Локальная `codex/device-passport-state-ux` содержит один неопубликованный
коммит — он сохранён отдельно. Backup не должен отслеживать origin/main.
