# Голосовой режим IRU

Голосовой цикл адаптирован из [DeepTalk](https://github.com/GiviSamali/DeepTalk):
браузерное распознавание русской речи, обращение «Иру», пауза 1 секунду
для отправки реплики, 10 секунд для продолжения разговора, Yandex SpeechKit
с голосом `zahar`, `neutral`, скоростью `1.2` и OggOpus.

## Поведение

- Кнопка микрофона или Ctrl+Shift+M включает/выключает режим.
- После включения нужно сказать «Иру». Распознавание работает только при явно включённом режиме.
- Голосовая реплика поступает в `/nl_command`, как текстовая. Используются
  выбранное устройство, текущий чат, режимы IRU, история и инструменты IRU.
  Текстовый черновик и вложения голосовой отправкой не затрагиваются.
- Во время отправки и выполнения микрофон выключен. Удаление и потенциально
  опасные команды подтверждаются только кнопками в чате. Остальные запросы
  подтверждения озвучиваются и принимают «да»/«нет» после окончания вопроса.
  Сервер отклоняет голосовое решение для опасной команды.
- Полный `answer` остаётся в чате. Для голоса короткий нетехнический ответ
  (до 220 символов) используется напрямую, остальные ответы сокращает базовая
  модель DeepSeek в 1–3 предложения (до 420 символов). Редактору передаются только
  исходный запрос, статус и основной ответ; инструменты ему недоступны.
  Инструкция требует сохранять ошибки, частичный успех и отсутствие проверки,
  исключая пути, команды и другие служебные подробности.
- Явные запросы вроде «назови полный путь», «где сохранён файл» или «расскажи
  подробно» сохраняют подробный ответ и inline-пути. Длинный текст в этом случае
  озвучивается частями. Обычное указание пути в команде не включает этот режим.
- Голосовой доклад кэшируется на задаче отдельно от текста чата; при изменении
  ответа, запроса или статуса кэш обновляется. Дополнительный LLM-вызов учитывается
  как `voice_brief`. На сокращение выделено 8 секунд. При сбое, обрезанном или
  некорректном результате озвучивается просьба прочитать полный ответ в чате,
  без выдуманного успеха и автоматического чтения длинного ответа.
- Карточки, команды и результаты инструментов не читаются; план озвучивается кратко.
  Блоки кода, URL и Markdown-разметка удаляются перед синтезом.
- Во время озвучки распознаются отдельные «стоп»/«Иру, стоп» и «усни».
  Это останавливает звук, не отменяя задачу. Есть отдельная кнопка
  «Остановить озвучку». Существующая кнопка остановки задачи сохраняет свою функцию.
- После ответа можно продолжить без обращения в течение 10 секунд.
- Новый/другой чат, выход и закрытие страницы выключают режим и сбрасывают
  очередь озвучки. При неопределённом состоянии задачи после сетевой ошибки
  режим выключается: пользователь проверяет задачу перед новым включением.

## Настройка сервера

В окружении процесса IRU задайте `YANDEX_API_KEY` сервисного аккаунта с правом
синтеза речи. Если используемая конфигурация требует каталог, задайте
`YANDEX_FOLDER_ID`. Секреты не должны попадать в Git или клиентский JavaScript.
Файл `.env` автоматически не загружается. IAM-токен в этой версии не поддерживается.

Сервер выполняет асинхронные запросы через уже используемый `httpx`.
Зависимости DeepTalk для локального воспроизведения звука не нужны.
Проверка конфигурации сообщает только доступность озвучки, без ключей.
При отсутствии настройки голосовой режим сообщает об этом; обычный чат работает.

API озвучки принимает ID задачи и номер части, проверяет авторизацию,
владельца и завершённость задачи. Текст берётся с сервера. Запросы ограничены
30 в минуту на пользователя отдельно от команд; одновременно синтезируется
не более одной части на пользователя. Аудио не сохраняется, ответ имеет `no-store`.
Провайдеру передаётся очищенный основной текст ответа.

Лимит частей выбран с запасом под ограничения
[SpeechKit API v1](https://yandex.cloud/ru/docs/speechkit/tts/request).

## Проверка

Автоматические проверки не обращаются к живому SpeechKit:

```text
python -m pytest -q tests/test_voice.py tests/test_voice_brief.py
node --test tests/voice-session.test.cjs
```

Браузерный smoke использует Playwright и установленный Edge, настоящий UI
и подменённые API, микрофон и AudioContext:

```text
python -m http.server 8769 --bind 127.0.0.1 --directory ui
node tests/voice-browser-smoke.cjs
```

Для полного pytest-набора существующие тесты Agent Shell запускаются отдельно
от остальных из-за конфликта импортов `agent`/`agent.shell`. При изолированной
БД задайте `IRU_DB_PATH` на временный файл и вызовите `database.init_db()` перед
тестами app_launch. Рабочая БД и реальные API-ключи для тестов не нужны.

Живой smoke после настройки сервера:

1. Открыть IRU по HTTPS (или localhost) в браузере с SpeechRecognition.
2. Включить режим и разрешить микрофон; сказать «Иру, привет».
3. После ответа продолжить разговор без обращения; после паузы >10 секунд
   проверить, что снова требуется «Иру».
4. Попросить действие на подключённом устройстве. Проверить паузу микрофона,
   подтверждение через UI и озвучку основного итогового ответа.
5. Во время ответа сказать «стоп»: звук прекращается, отмена задачи не вызывается.
6. Проверить смену чата и выключение режима во время подготовки аудио,
   ошибку SpeechKit и сохранение обычного текстового ввода.
7. Попросить создать файл: услышать короткий итог без пути, увидеть полный
   ответ в чате. Затем спросить «где сохранён файл»: услышать расположение.
   На задаче с частичным успехом проверить, что доклад сохраняет ограничение.

Реальный микрофон, акустическое эхо, голос SpeechKit и поддержка распознавания
в Agent Shell требуют отдельной живой проверки на целевом устройстве.


### Голосовой режим План

Предложение Плана озвучивается короткой фиксированной фразой без запроса к LLM.
После окончания озвучки в течение 30 секунд можно сказать «да», «запускай» или
«нет». Отказ продолжает исходный запрос без Плана. Неоднозначная речь не запускает
план; смена чата, новый запрос и выключение голоса сбрасывают ожидание.
«Стоп» во время озвучки прерывает только звук, без запуска задачи.
Голосовое согласие привязано к конкретному предложению, пользователю и чату;
повторный запуск по тому же предложению запрещён. Подтверждения опасных команд
остаются в интерфейсе. По завершении звучит краткий итог, без технического журнала.

Администратор (существующий системный user ID 1) освобождён от тарифного ограничения
Плана; имя пользователя само по себе прав не даёт. Ограничения остальных тарифов сохранены.
Голосовые задачи опрашиваются каждые 400 мс вместо 800 мс; текстовые — как раньше.
Пауза перед отправкой распознанной фразы уменьшена с 1500 до 1000 мс.
Последовательность планирования, исполнения и проверки результата не сокращалась:
её ускорение требует измерений на целевом сервере.

Проверка после обновления: сложный запрос → услышать предложение → «да» →
микрофон выключен → при необходимости подтвердить команду кнопкой → услышать итог.
Повторить с «нет», со сменой чата и под admin с уже использованным пробным запуском.


Команда «усни» (также «Иру, усни») переводит включённый голос в ожидание «Иру».
Она сбрасывает неотправленную фразу и голосовое ожидание подтверждения Плана,
останавливает текущую озвучку. Задачи не отменяются, предложение Плана в чате
остаётся доступным. После «усни» речь без обращения не отправляется.
Распознаётся только отдельная законченная команда; во время выполнения задачи
микрофон, как и прежде, выключен.


Перед исполнением готовый PLAN кратко озвучивается с вопросом «Хотите что-то изменить?».
«Нет» запускает план, «да» включает диктовку изменений и повторное планирование.
После «усни» ожидание проверки плана сохраняется; при следующем обращении
«Иру» план озвучивается заново до приёма согласия.

Короткий восходящий сигнал обозначает готовность принять речь, нисходящий —
завершение окна команд или выключение режима. Фоновое ожидание «Иру» после
«усни» сохраняется. Перезапуски распознавателя и прослушивание слова «стоп»
во время озвучки не создают повторных сигналов готовности.


### Повторная доставка распознанной речи

Для каждого экземпляра SpeechRecognition клиент отмечает индексы уже принятых
финальных результатов. Повторный result-event с теми же финальными индексами
не добавляет текст снова и не повторяет голосовое согласие. Новый индекс с тем
же текстом сохраняется: намеренные повторы слов не удаляются. После перезапуска
распознавателя индексы отслеживаются заново; поздние события старого экземпляра
по-прежнему игнорируются. Browser smoke воспроизводит промежуточные результаты,
повторную доставку финальных результатов и диктовку изменений PLAN.


### Android: повторяющиеся результаты распознавания

На Android браузерный recognizer запускается с `continuous = false`: один финальный результат завершает текущий цикл, затем через 250 мс начинается следующий, если голосовой режим продолжает слушать. Поздние события прежнего recognizer игнорируются. Это предотвращает накопление повторных cumulative finals под новыми индексами в continuous mode. Намеренно повторённые слова не удаляются из текста. На компьютере сохранён continuous mode с защитой от повторной доставки одного result index.

Проверка: `node --test tests/voice-session.test.cjs tests/voice-recognition.test.cjs` (39 тестов). Android Chrome/Comet с реальным микрофоном требуют проверки после обновления страницы; автоматические тесты используют имитацию SpeechRecognition.


### Wake word, пунктуация и обновление клиента

Пунктуация распознавания возле wake word не становится отдельным заданием.
Кроме фильтра в voice session, общий `sendMessage` отклоняет `voiceText`,
если в нём нет букв или цифр, до изменения chat history, открытия voice ticket
и HTTP-запроса. Это защищает и от другого либо устаревшего вызывающего кода.
Обычный текстовый ввод, в том числе намеренно введённая точка, не фильтруется.

HTML главной страницы отдаётся с `Cache-Control: no-cache`. Ссылки на
`chat.js`, `voice-session.js` и `voice.js` получают параметр `v` с SHA-256
текущего содержимого файла. После обновления сервера браузер/WebView2 получает
новый URL изменённого скрипта, даже если размер и mtime совпали. Очистка
профиля, потеря входа и пересборка агента для этого изменения не требуются.
Статический preview через `python -m http.server` не добавляет версии: это
делает серверный маршрут `/`.

После обновления сервера проверить:

```bash
curl -fsS https://irumode.ru/ | grep 'voice-session.js?v='
```

Затем обновить страницу через меню ИРУ или полностью закрыть и открыть
приложение. Проверка только наличия `const hasWords` в JS не доказывает,
что уже открытый клиент перезагрузил этот скрипт.

77 passed. Реальный Edge browser smoke с mocked speech/API проверил
`ИРУ.` и отдельную `.` через полный adapter/session/chat/HTTP путь, защиту
