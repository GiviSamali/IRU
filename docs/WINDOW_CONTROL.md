# Window Control: первый кластер

Ветка `codex/window-control`, база `0b821f5024fbf56c9e7aeecab85aed05c318e950`.

LLM → `window_control` → существующий controller/runtime → авторизованный WebSocket выбранного агента → `window.control` → WindowsAdapter → Win32 → проверенный результат. Один tool call за итерацию сохранён. PLAN получает тот же инструмент, но обычная композиция оконных действий не требует PLAN.

## Контракт

`action`: active, list, find, monitors, activate, minimize, maximize, restore, close, move, resize, left, right, move_monitor.

`target`: current (активное окно), last (последнее успешно изменённое окно на этом агенте), приложение или часть заголовка. Дополнительные фильтры: title, pid. `window_id` — непрозрачный ID из ответа capability; HWND модель не получает. ID привязан к HWND/PID, действует до исчезновения окна или перезапуска агента. При нескольких кандидатах возвращается ambiguous/candidates, действие не выполняется. Обычный controller сразу завершает текущий запрос вопросом пользователю, не позволяя модели самостоятельно выбрать кандидата. Для известного имени приложения сначала сопоставляется executable; браузер — группа известных браузеров, несколько окон требуют уточнения.

`device_id` проходит существующую проверку ownership и явную маршрутизацию. Неизвестное/отключённое/чужое устройство не получает fallback. Параметры allowlisted, неизвестные поля отвергаются. Произвольный код/API не принимается.

`move`: x,y. `resize`: width,height (1–32768). `left/right`: work area текущего либо указанного monitor. `move_monitor`: monitor обязателен, сохраняет размер насколько позволяет work area, размещает в её левом верхнем углу. Нумерация: основной монитор 1, остальные по координатам; актуальные номера возвращает monitors. Поддерживаются отрицательные координаты, taskbar и DPI context Per Monitor V2.

## Windows

ctypes Win32, pointer-sized HWND/HANDLE и явные сигнатуры. EnumWindows исключает shell/tool/cloaked окна без пользовательского заголовка. ShowWindowAsync, SetWindowPos (без изменения Z-order/фокуса), SetForegroundWindow, PostMessageW(WM_CLOSE). Никаких shell-команд, synthetic keyboard/mouse events или убийства процесса. Проверка изменённого состояния занимает до 0.3 секунды, закрытия до 0.75 секунды. WM_CLOSE при диалоге сохранения возвращает pending, UI показывает незавершённость, модель должна сообщить об ожидающем решении.

## Ответы

minimize/maximize/restore/activate/move/resize/left/right/move_monitor возвращают `response_policy=silent_on_success` только при проверенном успехе. Короткий результат сохраняется в UI и журнале. Голосовой endpoint возвращает 204 для задачи, состоящей только из успешных таких действий; TTS и дополнительный LLM для сокращения ответа не запускаются. Ошибки, неоднозначность, информационные запросы, close и смешанные задачи остаются голосовыми.

Обычный controller разрешает следующий window_control после успешного оконного действия и умеет завершить композицию по накопленным результатам, если модель не вызвала answer_text. Для распознанной обычной оконной команды доступны только window_control и инструменты ответа: execute_cmd/другой tool отвергается до отправки агенту. После подтверждения всей ожидаемой последовательности действий ответ формируется из evidence без отдельного LLM-вызова. Консервативный classifier fast path покрывает типовые оконные команды и их композиции, сохраняя классификацию остальных задач.

## Проверка на живом агенте

Требуется новая сборка агента: серверный UI reload не добавляет Win32 capability в старый exe. После обновления сервера и агента проверить:

1. Какие окна открыты? Какое окно активно?
2. Сверни браузер. Верни его.
3. Word вправо. Браузер влево.
4. Поставь браузер слева, а VS Code справа.
5. Два окна Word: сверни Word → уточнение, без случайного выбора.
6. Перенеси Word на второй монитор.
7. Сверни браузер на Second; затем проверить отказ с отключённым Second.
8. Закрой блокнот с несохранённым текстом → штатный диалог остаётся пользователю.

## Ограничения

Windows 10/11; на других ОС структурированный отказ без shell fallback. Windows может запретить перевод фокуса, elevated приложения могут отвергать действия обычного агента. Приложение может ограничивать минимальный размер/позицию: неподтверждённая геометрия не считается успехом. Полноэкранные игры/нестандартные окна могут не поддерживать операции. `last` хранится локально на агенте, общая очередь параллельных запросов может изменить последнее окно; для точного выбора использовать window_id. Мониторные номера не являются постоянными идентификаторами после изменения подключения мониторов.

Автотесты используют fake Win32 adapter; дополнительная локальная проверка list/monitors использует настоящий Win32 без изменения окон. Финальная проверка действий/фокуса/DPI на двух устройствах выполняется пользователем.
